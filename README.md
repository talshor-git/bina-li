# בינה לי

האתר המלווה לסדנת הבינה המלאכותית — פיד כלים, פרומפטים, יצירות משותפות ולייקים.

האתר הוא קובץ `index.html` יחיד (התמונות מוטמעות בו), והנתונים נשמרים ב-**Firebase Firestore**.

**אין הרשמה ואין התחברות:** המשתתפים לא ממלאים שם משתמש או סיסמה, ואין מסך כניסה. כל דפדפן מקבל מזהה אנונימי אוטומטי ושקוף מאחורי הקלעים.

## העלאת תוכן

יש שני כפתורים נפרדים בראש העמוד, וכל אחד פותח טופס משלו:

- **כלי חדש** — שם הכלי, תיאור, קישור לכלי (חובה), תמונה מייצגת, איך משתמשים ותגים.
- **פרומפט חדש** — שם הפרומפט, תיאור, הפרומפט עצמו (חובה), איך משתמשים ותגים.

אין ערבוב בין הטפסים. כלי נשמר עם `type: "tool"` ופרומפט עם `type: "prompt"`.

## הפעלה ראשונה של Firebase (חד-פעמי)

יש לעבור בקונסולת Firebase של הפרויקט `bina-li`:

### 1. יצירת Firestore

1. נכנסים ל־[console.firebase.google.com](https://console.firebase.google.com) ובוחרים את הפרויקט **bina-li**.
2. בתפריט הצד: **Build → Firestore Database → Create database**.
3. בוחרים **Production mode** (לא Test mode).
4. בוחרים אזור (Location), למשל `europe-west1`, ומאשרים.

### 2. הפעלת זיהוי אנונימי (לא התחברות!)

**אין כאן שם משתמש, סיסמה או מסך כניסה.** המשתתפים לא מתחברים לשום דבר.

1. **Build → Authentication → Get started**.
2. בכרטיסיית **Sign-in method** לוחצים על **Anonymous**.
3. מפעילים (Enable) ושומרים.

Firebase מייצר אוטומטית מזהה אקראי לכל דפדפן. המזהה שקוף למשתמש, ומשמש רק כדי למנוע לייק כפול ולאפשר כתיבה מאובטחת ל-Firestore.

### 3. פרסום חוקי האבטחה

1. **Build → Firestore Database → Rules**.
2. מוחקים את התוכן הקיים ומדביקים את התוכן של הקובץ [`firestore.rules`](firestore.rules).
3. לוחצים **Publish**.

> אין להשאיר את החוקים במצב `allow read, write: if true`. זה מאפשר לכל מבקר באתר לשנות או למחוק את כל הפיד.

### 4. (אופציונלי) הוספת הדומיין של GitHub Pages

אין חובה בשלב הזה עבור זיהוי אנונימי. הוא נדרש רק אם בעתיד תוסיפו התחברות עם Google או ספק אחר.

1. **Build → Authentication → Settings → Authorized domains**.
2. מוסיפים: `talshor-git.github.io`
3. אם בעתיד יחובר דומיין משלכם — מוסיפים גם אותו.

### 5. טעינה ראשונה

פותחים את האתר. אם אין עדיין פוסטים, מוצג מסך **"הפיד עדיין ריק"** עם שני כפתורים להוספת כלי או פרומפט. אין זריעה אוטומטית — הפיד נשאר ריק עד שמוסיפים תוכן.

אם מופיע "הפיד לא נטען":
- פותחים את כלי המפתחים (F12) ובודקים את ה-Console.
- `auth/configuration-not-found` = אימות אנונימי לא הופעל.
- `permission-denied` = חוקי Firestore לא פורסמו.
- `not-found` / `Failed to get document` = מסד הנתונים עוד לא נוצר.

## מבנה הנתונים

אוסף אחד: `posts`. כל מסמך הוא פוסט:

```
posts/{postId}
  type: "tool" | "prompt"
  created: number (מילישניות)
  title, desc, url, image, usage, snippet: string
  tags: string[]
  likes: number
  likedBy: string[]          // uid-ים שכבר עשו לייק
  links: [                   // "תגובות" — יצירות משותפות
    { id, name, url, title, likes, likedBy: string[], created, createdBy }
  ]
  createdBy: string          // uid של היוצר
```

- **פוסט** = מסמך ב-`posts`.
- **תגובה / יצירה** = איבר במערך `links` של הפוסט.
- **לייק** = `likes` בתוספת ה-uid של המשתמש ב-`likedBy`, כדי שלא ייספר פעמיים.
- העדכונים מגיעים בזמן אמת דרך `onSnapshot`, בלי רענון עמוד.

## מחיקת תוכן

פוסטים שיצרת **בסשן הנוכחי** (עד סגירת הטאב) מציגים אייקון פח בכרטיס הפוסט. לחיצה עליו מבקשת אישור ומוחקת את הפוסט גם מ-Firestore.

- המחיקה מוגנת בחוקים: רק היוצר (`createdBy`) יכול למחוק את הפוסט.
- אם האייקון לא מופיע, הפוסט לא נוצר בסשן הזה (למשל אחרי סגירת הטאב או פתיחה בטאב אחר).
- אם המחיקה נכשלת עם `permission-denied`, יש לפרסם את `firestore.rules` המעודכן.
- פוסטים ישנים או פוסטים של אחרים נמחקים דרך הקונסולה: **Firestore Database → posts → בוחרים מסמך → Delete**.

## עדכון האתר

בכל שינוי מעלים את מספר הגרסה ב-`APP_VERSION` שבקובץ `index.html` (הוא מוצג אוטומטית בפוטר).

```bash
git add -A
git commit -m "update"
git push
```

GitHub Pages מתעדכן אוטומטית תוך דקה־שתיים.
